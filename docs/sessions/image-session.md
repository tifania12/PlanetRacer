# 이미지 생성 세션 절차 (ChatGPT 데스크탑 앱)

예약 작업 지시문이 **이 파일을 읽고 그대로 따르게** 되어 있다.
절차를 고칠 일이 생기면 예약 작업을 건드리지 말고 **이 파일만 고친다**
(예약 작업은 PC에 묶여 있어서 지시문을 바꾸려면 Tifania의 승인이 매번 필요하다).

## 0. 전제 — 하나라도 안 맞으면 아무것도 하지 않고 daily에 이유만 적고 끝낸다

1. **지금이 20:00~08:00 KST 사이**인가. 아니면 끝.
2. **PC가 유휴 상태인가** — `GetLastInputInfo`로 **300초 이상**. Tifania가 PC를 쓰고 있으면
   타이핑이 엉뚱한 창(카카오톡 등)으로 새어 들어간다. 실제로 그런 적 있다. 아니면 끝.
3. **ChatGPT 데스크탑 앱이 떠 있는가.** 없으면 `Windows-MCP`의 `App`으로 띄운다.
4. **`docs/design/art-requests.md`의 "대기 중"에 항목이 남아 있는가.** 없으면 끝.
   비어 있으면 **그게 이 세션의 할 일이다** — 설계 문서(`pet-gacha.md` 7절 등)에서
   프롬프트를 뽑아 채운다. "다른 세션 몫"이라고 적고 끝내지 않는다(CLAUDE.md 규칙 하나).
5. **앞 세션이 이미지 한도에 걸렸는가.** 오늘 daily에 `이미지 한도 — N시간 후 풀림`이 있고
   그 시각이 아직 안 지났으면 **아무것도 하지 않는다.** 한 줄만 남기고 끝낸다.
   한도가 풀릴 때까지 매 세션 시도해 봐야 똑같이 거절당한다.

## 1. 캡처 준비 — 화면 보호기를 먼저 치운다 (이게 나흘 내내 0장이었던 이유다)

**캡처를 시도하기 전에 반드시 이걸 먼저 돌린다.** Windows-MCP PowerShell로:

    powershell -ExecutionPolicy Bypass -File "E:\Unity\PlanetRacer\tools\prepare_capture.ps1"

마지막 줄이 판정이다.

- `CAPTURE-OK` → 캡처해도 된다. 2절로 간다.
- `CAPTURE-BLOCKED ...` → **거기서 멈춘다.** 그 줄을 daily에 그대로 옮겨 적고 끝낸다.
  보지 못하는 상태로 타이핑하거나 클릭하지 않는다. 되풀이해서 시도하지 않는다.

**왜 필요한가.** 이 PC는 화면 보호기가 **600초(10분)**에 뜬다. 그런데 이 세션은 스스로
"유휴 300초 이상일 때만 움직인다"는 규칙을 갖고 있다. 그래서 세션이 화면을 보려는 시점엔
거의 언제나 화면 보호기가 이미 떠 있다. 화면 보호기는 자기 전용 데스크톱(`Screen-saver`)에서
돌기 때문에, 기본 데스크톱에 붙어 있는 캡처 도구는 `액세스가 거부되었습니다`로 막힌다.
위 스크립트는 **마우스나 키를 흉내 내지 않고 화면 보호기 프로세스만 끝낸다** —
Tifania가 PC를 쓰는 중이어도 커서가 튀거나 창이 눌리지 않는다.

**틀린 진단 두 개(되풀이하지 말 것).**
- `Mountain Base Camp`·XBOX·NVIDIA 오버레이·유튜브 탭 때문이 **아니다.**
  2026-09-17 아침에 그 창들이 전부 떠 있는 상태에서 캡처가 정상으로 됐다.
- "스크린샷과 앱" 권한 문제도 **아니다.** 이미 켜져 있고, 사람이 PC 앞에 있을 때는 늘 된다.
  캡처 성공/실패를 가른 건 창 목록도 권한도 아니고 **유휴 시간**이었다.

**그래도 막히면 무엇을 적을 것인가.** 스크립트가 찍는 `입력 데스크톱:` 줄을 daily에 남긴다.
`Winlogon`이면 화면이 잠긴 것이라 세션이 풀 수 없다(Tifania가 잠금을 끄거나 자동 잠금을 꺼야 한다).
`Default`인데도 캡처가 막히면 그건 새로운 원인이니 창 목록까지 같이 적는다.

## 1-2. 긴 대기 뒤에는 다시 확인한다

그림 한 장을 기다리는 데 1분쯤 걸리므로 보통은 문제없지만, **10분 넘게 입력 없이 기다렸다면
다음 캡처 전에 1절 스크립트를 한 번 더 돌린다.** 그 사이 화면 보호기가 다시 떴을 수 있다.

## 1-3. 하루 한도가 있다 — 한 세션이 다 쓰지 않는다

ChatGPT Plus는 이미지 생성에 **14시간짜리 한도**가 있다. 2026-09-20 밤에 00시·03시 세션이
**46장**을 몰아 뽑은 뒤 06시 세션이 네 장째에서
`"지금은 이미지 생성 메시지를 모두 사용했습니다. 14시간 후에 다시 시도하세요"`로 끊겼다.

**그래서 세션당 12장까지만 뽑는다.** 밤에 여섯 번 도니(20·22·00·02·04·06시) 하루 72장이 되는데,
한도가 그보다 낮으면 어차피 중간에 걸린다. 12장으로 끊어 두면 **뒤 세션도 몫이 남는다.**
12장을 채웠으면 시간이 남아도 그만둔다 — daily에 "세션 상한 12장 채움"이라고 적는다.

한도 메시지를 만나면 **그 자리에서 끝낸다.** 다시 시도하지 않는다.
daily에 `이미지 한도 — N시간 후 풀림`이라고 적고, 남은 대기 장수를 같이 적는다.

## 2. 프로젝트 `Gem Racer` 안에서, 계열마다 대화방 하나 (2026-09-20)

Tifania: "프로젝트 하나 만들어서 채팅방을 펫이면 펫, 자동차면 자동차로 만들어서 관리해야
이미지가 일관되게 나올 것 같은데."

맞다. 112장이 한 세계처럼 보이려면 **같은 계열은 같은 대화에서 이어 뽑아야** 한다.
GPT가 앞에 뽑은 것을 참고해서 다음 것을 맞춰 주기 때문이다.
전에 적어 둔 "한 대화에 한 장"은 **다른 종류끼리 섞이는 것**을 막으려던 규칙이었는데,
같은 계열 안에서는 오히려 이어 가는 쪽이 맞다. 그 규칙 때문에 09-20까지 자동 제목 채팅이
서른다섯 개 넘게 쌓였고, 그게 그림이 제각각인 이유였다.

### 프로젝트는 이미 있다 — `Gem Racer`

**Tifania가 2026-09-20에 만들고 프로젝트 지침까지 넣어 뒀다.**
ChatGPT 데스크탑 앱 사이드바의 **「프로젝트」** 목록 안에 있다(`codex`·`AI_Memory` 등과 나란히).

- **새 방을 여는 확실한 방법은 사이드바의 프로젝트 줄에 마우스를 올렸을 때 오른쪽 끝에 나타나는
  연필 아이콘(✎)을 누르는 것이다.** 입력칸에 **`Gem Racer의 새 채팅`** 이라고 뜨고,
  **거기서 보낸 첫 메시지가 그 프로젝트 안의 새 방이 된다.**
  (프로젝트 이름을 그냥 누르면 접혔다 펴지기만 하고 새 방은 안 생긴다 — 09-20에 확인했다.)
- 프로젝트 지침이 모든 방에 자동으로 걸린다. 그래서 프롬프트의 스타일 고정문이 겹쳐도 해가 없다 —
  **장부의 프롬프트는 고치지 말고 그대로 붙여 넣는다.**
- 사이드바 맨 위 **「고정된 스레드」** 에 자주 쓰는 방을 올려 두면 찾기 쉽다.

### 방은 계열마다 하나

| 대화방 | 뽑는 것 |
|---|---|
| `바퀴족 설정 기억` | `Pets/**/wheel-*` — **있다**(09-20, 프로젝트 안) |
| `날개족 설정 기억` | `Pets/**/wing-*` — **있다**(09-20, 프로젝트 안) |
| `펫 — 광석족` | `Pets/**/ore-*` — **있다**(09-20, 고정된 스레드에도 올려 둠) |
| `짐꾼족 설정 기억` | `Pets/**/haul-*` · `carrier-*` — **있다**(09-20, 프로젝트 안) |
| `초월 등급 설정 기억` | `Pets/7-transcend/*` — **있다**(09-20, 프로젝트 안). 열 마리가 서로 달라야 해서 따로 |
| `컷신` | `Cutscenes/*` |
| `아이콘` | `Icons/*` |
| `탈것` | `Rigs/*` · 레이싱카 |
| `행성` | `Planets/*` |

**규칙 셋.**
1. 뽑으려는 항목의 경로를 보고 **그 계열의 방으로 간다.**
   없으면 **`Gem Racer` 프로젝트를 열고 거기서** 새 방을 만든다(프로젝트 밖에 만들지 않는다).
2. **같은 방 안에서는 새 대화를 열지 않고 이어서 뽑는다.** 그래야 계열이 한 족보로 보인다.
3. **방을 넘어갈 때만** 옮긴다. 아이콘 뽑다가 펫을 같은 방에서 뽑지 않는다.

### 새 방을 만들 때 — 첫 메시지로 계열을 못 박는다

프로젝트 지침이 전체 톤을 잡아 주니, 첫 메시지는 **그 계열만의 생김새**를 적는다.
`docs/design/pet-gacha.md` 7절의 계열 표를 그대로 옮기면 된다. 예(광석족):

    이 방은 "보석 행성 레이서"의 펫 — 광석족 이미지만 뽑는 방입니다.
    다른 계열이나 아이콘·컷신은 여기서 뽑지 않습니다.
    - 결정 덩어리 몸통에 큰 눈 두 개가 앞면에 박혀 있는 작은 생물
    - 등급이 오르면 새 생물이 되는 게 아니라 같은 생물이 자란 모습
    지금은 생성하지 말고, 기억했다고만 한 줄로 답해 주세요.

**이름은 GPT가 붙인 자동 제목 그대로 둔다.** 데스크탑 앱에서 오른쪽 클릭 → `이름 변경`
(`Alt+Ctrl+R`)을 눌러도 입력 상태로 들어가지 않는다 — 09-20에 다섯 번 시도해 전부 실패했다.
`Ctrl+A`가 사이드바가 아니라 대화 본문을 잡는 것으로 확인했다. **방 제목은 GPT의 행동에
아무 영향이 없으니 매달리지 않는다.** 대신 **첫 메시지에 계열을 못 박아 두는 것**이 실제
장치다. 굳이 이름을 바꿔야 하면 브라우저(chatgpt.com)에서 하거나 Tifania에게 맡긴다.

그래도 이름 칸에 붙여 넣을 일이 생기면, **입력 상태가 됐는지 캡처로 확인하고 나서** 붙여 넣는다.
확인 없이 바로 붙여 넣으면 채팅 입력창으로 들어가 **빈 채팅이 하나 더 생긴다**
(2026-09-20에 실제로 그랬다 — `광석족 설정 기억、】【`).

**프로젝트 밖에 만들어진 방은 옮길 수 있다.** 사이드바에서 그 채팅을 오른쪽 클릭 →
`프로젝트` → `Gem Racer`. 이건 09-20에 실제로 동작했다(`이름 변경`과 달리).

## 2-2. 한 장 뽑는 절차 (항목 하나당 반복, 대략 3분에 한 장)

1. **위 표대로 그 계열의 대화방을 연다.** 같은 방이면 새 대화를 열지 않고 이어 쓴다.
2. **프롬프트는 클립보드로 붙여 넣는다.** `Clipboard`로 넣고 `Ctrl+V`.
   키보드로 직접 타이핑하지 않는다 — 창이 바뀌면 그대로 새어 나간다.
   **`Clipboard set`이 성공했다고 답해도 앞 내용이 붙는 일이 있다**(2026-09-22 00시에 두 번).
   붙여 넣기 전에 `Get-Clipboard`로 첫 20자가 `Style: clean stylize`인지 확인한다.
   (`$`가 들어가는 명령은 `-Command`에서 먹히니 `.ps1` 파일로 써서 `powershell -File`로 부른다 —
   `tools/clip_check.ps1`이 그 용도로 이미 있다. 유휴 시간은 `tools/idle_check.ps1`.)
3. 엔터. 그림이 나올 때까지 기다린다(보통 60~110초). **기다린 뒤에는 클릭하기 전에 반드시
   캡처로 먼저 본다.**
   **그리고 오른쪽 클릭 전에 반드시 「맨 아래로 스크롤」(입력창 바로 위 동그란 버튼)을 먼저 누른다.**
   프롬프트를 보내도 대화가 바닥까지 안 내려가는 경우가 절반쯤 된다. 그때 화면 맨 위에 보이는 그림은
   **새로 뽑은 것이 아니라 앞 세션이 남긴 그림**이고, 거기에 오른쪽 클릭을 하면 그 옛 그림이 받힌다
   (2026-09-22 04시에 실제로 그랬다 — 02시 세션의 `ore-07`과 MD5가 같은 파일이 `ore-02` 자리에 들어갔다).
   바닥에 내려간 화면은 **위에 사용자 말풍선, 아래에 새 그림** 순서로 보인다.
   그림 위에 말풍선이 없고 그림부터 보이면 아직 안 내려간 것이다. 기다리는 동안 다른 창이 스스로 앞으로 튀어나올 수 있다 —
   2026-09-20에 크롬(LMS 강의 재생 페이지)이 그래서, 안 보고 누른 오른쪽 클릭이
   크롬 메뉴를 열었다. `Esc`로 닫고 `App(mode=switch, name=ChatGPT)`로 되돌린 뒤 이어 하면 된다.
   (이때 유휴 시간을 다시 재도 소용없다 — 이 세션이 누른 키·클릭도 유휴를 0으로 만들기 때문에,
   유휴 검사는 **움직이기 전 한 번만** 뜻이 있다. 사람이 왔는지 보려면 입력을 아예 안 주고
   1분쯤 기다렸다가 재야 한다.)
4. **저장은 오른쪽 클릭 → "사본 다운로드". 이 길을 기본으로 쓴다.**
   - **⚠ 그림을 클릭해 여는 「이미지 편집기 탭」으로는 받지 말 것 (2026-09-21 20시에 찾은 버그).**
     앞서 열었던 편집기 탭이 살아 있으면 **그때 고른 썸네일이 선택된 채 다시 열리고**,
     오른쪽 위 내려받기는 화면에 보이는 그림이 아니라 **선택된 썸네일**을 준다.
     실제로 3차 `ore-02`가 직전 `ore-07`과 **바이트 단위로 같은 파일**로 받혔다(MD5 동일).
     캡처로 새 그림을 봐도 속는다 — **보고 확인해도 못 거르는 종류다.**
     오른쪽 클릭 경로는 항상 그 메시지의 그림을 준다.
   - **받은 뒤에는 MD5로 앞 파일과 다른지 확인한다. 선택이 아니라 필수다**(한 세션에서 여러 장 받을 때).
     device_bash에서 `md5sum <파일>`이면 된다. 같은 값이 나오면 **엉뚱한 그림을 받은 것**이니
     3번의 「맨 아래로 스크롤」부터 다시 한다.
   - **같은 항목을 여러 번 돌릴 때는 자리 파일에 바로 덮어쓰지 말 것.**
     `Assets\Screenshots\cand.png`(gitignore됨)로 받아 검사한 뒤 **앞 회차보다 좋을 때만**
     device_bash `cp`로 자리에 옮긴다. 그냥 덮어쓰면 어렵게 나온 낮은 값이 다음 회차에 사라진다
     (2026-09-22 04시에 329와 283을 그렇게 잃었다). 끝나고 `cand.png`는 Windows-MCP PowerShell로 지운다.
   - 저장 대화상자의 파일 이름 칸은 **세 번 클릭으로 전체 선택이 안 된다**(기존 이름 뒤에 붙는다).
     반드시 `Ctrl+A`를 먼저 누르고 붙여 넣는다.
   - **메뉴가 안 뜨면 라이트박스를 거친다(2026-09-20에 찾은 우회로).** 그림이 다 나왔는데도

## 3. 넣기 전에 반드시 검사한다

**검사가 두 종류다. `art-requests.md`의 그 항목 "참고" 줄을 보고 고른다.**

| 참고 줄이 | 쓰는 명령 | 보는 것 |
|---|---|---|
| "투명 PNG로 받는다" (아이콘·행성·펫 등) | `python tools/check_alpha.py <파일>` | RGBA인가 / 모서리가 투명한가 / 투명 영역 10~95% / 마젠타 잔상 |
| **"배경 제거 안 함"** (컷신 등) | `python tools/check_alpha.py --opaque <파일>` | 열리는가 / 폭 1600px 이상 / 단색이 아닌가 / 마젠타 잔상 |

**통과(exit 0)해야만 그 파일을 커밋한다.**

**모드를 잘못 고르지 말 것.** 불투명 그림에 투명 모드를 쓰면 "알파 채널이 없다"로
**반드시** 실패한다 — 그림이 나빠서가 아니라 검사가 안 맞는 것이다.
2026-09-17~18에 이것 때문에 이미지 세션이 네 번 연속 같은 자리에서 멈췄다(`decisions.md` T-11).
실패 메시지가 "알파 채널이 없다 (모드 RGB)"인데 장부 참고가 "배경 제거 안 함"이면
**모드를 잘못 고른 것이다. `--opaque`를 붙여 다시 돌린다.**

실패하면 그 파일은 지우지 말고 그대로 두되 커밋하지 않는다. daily에
"`<파일명>` 검사 실패 — <출력 줄>"이라고 적고 **다음 항목으로 넘어간다.**
같은 항목을 그 자리에서 다시 뽑느라 시간을 쓰지 않는다.

> 배경 제거(`tools/strip_bg.py`)는 더 이상 기본 경로가 아니다. 2026-09-16부터
> 프롬프트에 `real alpha channel` + `no background color`를 넣어 **처음부터 투명 PNG로 받는다.**
> 키잉은 테두리에 분홍 잔상을 남긴다(icon-key.png에서 2813픽셀 확인).
> 배경이 붙어 온 그림이 생기면 그때만 `strip_bg.py`를 톨러런스 60으로 쓴다.

## 5. 커밋

git 작업 전에 `.git/**/*.lock`을 Windows-MCP PowerShell로 지운다(device_bash는 파일을 못 지운다).
**`powershell -ExecutionPolicy Bypass -File "E:\Unity\PlanetRacer\tools\clear_git_locks.ps1"` 한 줄이면 된다**
(`-Command`로 쓰면 `$_`가 먹혀서 아무것도 안 지워진다 — 2026-09-22 04시에 확인).

**device_bash의 git은 파일을 지우지 못해 반쯤만 동작한다.** `commit`은 되지만 끝나고 `index.lock`을
못 지워서 **다음 git 명령이 전부 막힌다.** `checkout --`·`stash push`는 아예 조용히 실패한다
(오류도 안 낸다). 그래서 **stash·rebase·push는 Windows-MCP PowerShell에서 돌린다** — 거기선 지우기가 된다.
device_bash는 파일을 읽고 고치는 데만 쓰고, git 조작은 PowerShell 쪽으로 넘기는 것이 맞다.
한글 커밋 메시지는 `.commitmsg`에 heredoc으로 써서 `git commit -F .commitmsg`.

**커밋했으면 그 자리에서 푸시한다 (2026-09-20).** 로컬에만 있는 커밋은 다른 세션이
`claude/dev`를 origin으로 하드 리셋하면 통째로 사라진다 — 9/20 01시에 실제로
`cd512e8`·`c896ee8`과 PNG 여섯 장이 그렇게 날아갔고, 이어서 16커밋(전설 펫 20장 포함)이
02:51까지 푸시되지 않은 채 쌓여 있었다. 한 장씩 뽑을 때마다 푸시할 필요는 없지만
**세션을 끝내기 전에는 반드시** 아래까지 한다.

    git pull --rebase origin claude/dev
    git push origin HEAD:claude/dev

`docs/daily/*.md`에서 충돌이 나는 게 보통이다(여러 세션이 같은 날 파일에 각자 절을 붙인다).
그때는 **양쪽 절을 다 남기고** 충돌 표식 세 줄만 지우면 된다 — 고를 일이 아니다.
