### 16:50 — UI가 살아나자마자 스택 오버플로

Tifania가 웹에서 `RangeError: Maximum call stack size exceeded`를 받았다. 스택이
`invoke_iii` → wasm 프레임 네댓 개를 계속 반복한다. UI가 안 보이던 빌드에서는 안 나던 오류다.
즉 `stripEngineCode`를 끄면서 UI Toolkit이 살아났고, 그러자마자 이걸로 죽은 것이다.

**무한 재귀가 아니라 스택이 작아서로 본다.** UI Toolkit 레이아웃은 비주얼 트리를 재귀로 훑는데
emscripten 기본 스택 크기가 64KB다(emscripten 3.1.27부터 5MB에서 64KB로 줄었다).
UIDocument 여덟 개가 한 패널에 붙어 있으니 트리가 깊고, 첫 레이아웃 패스에서 그대로 넘친다.
에디터에서는 스택이 넉넉해서 멀쩡히 돌았던 것과 앞뒤가 맞는다.

`ResponsiveLayout`의 `GeometryChangedEvent` 재진입도 의심해서 코드를 봤는데,
`Apply()`가 `Screen.width/height`가 그대로면 바로 빠져나오게 되어 있어 무한히 돌 구조는 아니다.
다른 패널 중 기하 콜백을 등록하는 것도 없다.

고친 것 세 가지. 전부 `ProjectSettings.asset`까지 들어간 것을 확인했다(CI는 ApplySettings를 안 부른다).

- `webGLEmscriptenArgs`: 빈 값 → `-sSTACK_SIZE=5242880` (5MB)
- `webGLExceptionSupport`: `None`(0) → `ExplicitlyThrownExceptionsOnly`(1).
  None이면 C# 예외가 터져도 브라우저에 정체불명 스택만 남는다. 지금은 원인을 보는 게 우선이라
  켠다 — **출시 직전에 다시 줄일 것**(용량·속도).
- `webGLInitialMemorySize`: 32 → 256 MB. 32MB는 초반 성장 스톨이 잦다.

에디터 Game View를 세로 540x960으로 추가해 뒀다(리플렉션으로 GameViewSizes에 등록).
backlog W-05가 "API가 비공개라 못 했다"고 남긴 것인데 되는 경로를 찾았으니 W-05도 이걸로 풀린다.

### 17:40 — 오늘 세 번의 배포가 사실 반영되지 않고 있었다

스택 크기를 고친 빌드가 올라간 뒤에도 같은 오류가 나서 파일 크기를 재 봤다.

    wasm(브로틀리 전송분) = 8,482,954 바이트

**세 번의 빌드가 전부 바이트 단위로 똑같다.** `stripEngineCode`를 끄고, `exceptionSupport`를
켜고, 초기 힙을 여덟 배로 올렸는데 wasm이 1바이트도 안 변할 수는 없다. ETag도 그대로다.
즉 **빌드는 성공했지만 브라우저가 받는 건 계속 예전 파일이었다.**

원인은 `web/_headers`와 고정된 파일 이름의 조합이다.

    /Build/*.wasm.br
      Cache-Control: public, max-age=31536000, immutable

`immutable`은 "이 URL의 내용은 절대 안 바뀐다"는 선언이다. 그런데 `nameFilesAsHashes`가
꺼져 있어서 파일 이름이 매번 `PlanetRacer.wasm.br`로 같았다. 같은 URL + immutable + 1년 =
**한 번 받은 파일을 1년 동안 다시 안 받는다.** index.html은 이 규칙에 안 걸려서 갱신됐고,
그래서 "템플릿은 바뀌었는데 게임은 그대로"라는 앞뒤 안 맞는 상황이 나왔다.

고친 것.

- `nameFilesAsHashes`를 켰다. 이제 파일 이름에 내용 해시가 들어가서 빌드가 바뀌면 URL이 바뀐다.
  `immutable`이 그제서야 맞는 말이 된다. `_headers`의 `/Build/*.wasm.br` 같은 와일드카드는
  해시 이름에도 그대로 걸리므로 손댈 필요가 없다.
- `tools/check_web_deploy.js`가 파일 이름을 하드코딩하고 있었다. 이름이 고정이던 시절에는
  그게 곧 "캐시에 남은 옛날 파일을 확인하고 성공이라고 말하는" 구조였다 —
  **오늘 배포 확인이 계속 통과한 이유가 이것이다.** index.html을 먼저 받아서 거기 적힌
  실제 파일 이름을 뽑아 쓰도록 고쳤다.

교훈 하나. "빌드 성공 + http 200"은 배포가 반영됐다는 증거가 아니다. 내용이 바뀌었는지를 봐야 한다.
