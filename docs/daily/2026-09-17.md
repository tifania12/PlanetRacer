이런 식이면 내가 잘못된 걸 모르는 상태로 배포를 하게 만드는 일 아냐?"

맞는 말이었다. 승격 명령을 Tifania가 친다는 것만으로는 "사람이 확인하고 배포한다"가
성립하지 않는다 — 확인할 대상이 없으면 요식행위고, 잘못된 게 나가도 민 사람만 Tifania가 된다.

그래서 확인할 주소가 정말 없는지 찾아봤더니 **있었다.**

    https://dev.planetracer-daz.pages.dev

`webgl.yml`이 `claude/dev` 푸시마다 `--branch=dev`로 올리고 있었다. 승격도 승인도 필요 없고
배포 주소는 안 건드린다. 그런데 **어느 문서에도 이 주소가 없어서** 그동안 아무도 안 봤고,
밤 세션들은 아침 가이드에 "승격해야 보인다"고 계속 적어 왔다. 틀린 안내였다.

열어서 확인했다 — 제련소 줄이 그대로 나온다:

    원석 32.0  ·  정제 광물 0.0
    곡괭이 Lv.1 [업그레이드 (정제 15)]   화물칸 Lv.1 [업그레이드 (정제 25)]
    엔진  Lv.1 [업그레이드 (정제 20)]   제련소 Lv.0 [업그레이드 (원석 120)]
                                        다음: 시간당 정제 38 (현재 0)

CLAUDE.md에 "확인용 주소가 따로 있다"로 적고, 순서를 못 박았다:
밤 세션 푸시 → dev 자동 배포 → **아침에 Tifania가 dev를 만져 본다** → 그다음 승격.

곁들여, 승격 명령은 `cd /d`로 적기로 했다. 윈도우 cmd는 `cd E:\...`만으로는 드라이브가
안 바뀌어서 `not a git repository`가 난다 — 오늘 실제로 두 번 겪었다.

### 제련소를 업그레이드 화면 맨 앞으로

Tifania: "업그레이드 맨 앞에 제련소가 와야 하는 거 아냐?"

맞다. 새 채굴차는 정제 광물이 0이라 곡괭이·화물칸·엔진 셋을 **아예 못 누른다.**
그런데 제련소가 네 번째(오른쪽 아래)에 있으면, 화면을 열었을 때 회색 버튼 셋이 먼저 보이고
유일하게 누를 수 있는 것이 구석에 숨는다. 실제로 눌러야 하는 순서와 거꾸로다.

    제련소 Lv.0  [업그레이드 (원석 120)]   ← 맨 앞
    곡괭이 Lv.1  [업그레이드 (정제 15)]
    화물칸 Lv.1  [업그레이드 (정제 25)]
    엔진   Lv.1  [업그레이드 (정제 20)]

`BootstrapUpgradeUgui.cs`의 `MakeRow` 순서를 바꾸고 `GemRacer/16`을 다시 돌려 씬에 반영,
`MainHudUgui.upgradePanel` 재배선 후 저장. `UpgradeUgui.Refresh()`의 `SetRow` 순서도
화면 순서와 맞췄다(코드를 읽는 사람이 헷갈리지 않게).

Play로 확인 — `row-list` 자식 순서가 `row-refinery` / `row-tool` / `row-cargo` / `row-engine`.
