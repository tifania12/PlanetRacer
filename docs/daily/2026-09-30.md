### 2. 진짜 건진 건 이쪽이다 — 9-slice 테두리가 **4배로** 부풀고 있었다

메뉴를 누르고 플레이해서 찍어 보니 **카드 옆선이 안쪽으로 크게 휘고, 버튼 알약 끝이 칸 밖으로
삐져나와** 있었다. 그림 탓인 줄 알고 `ui-panel.png`을 열어 봤는데 멀쩡한 둥근 사각형이었다.

값을 직접 읽어 보고 알았다.

    row-refinery: 그림 ui-panel, sprite.pixelsPerUnit = 24.88, border = 21.67, mult = 1
    → 화면 테두리 = 21.67 x (100 / 24.88) = 87단위

uGUI는 9-slice 테두리를 그림 픽셀 그대로 쓰지 않고 **`referencePixelsPerUnit / sprite.pixelsPerUnit`**
만큼 키운다. 우리 UI 그림은 임포트에서 1028 → 256으로 줄면서 `pixelsPerUnit`이 100이 아니라
**25 안팎**이 된다. 그래서 21.67px 테두리가 화면에서 **87단위**가 되고, 높이 168짜리 카드에서
위아래 모서리가 156을 먹어 가운데가 12밖에 안 남았다. 그게 휘어 보인 이유다.

**고친 방법** — `UiSkin.SliceMultiplier(img, sprite)`가 배수를 자동으로 구한다.

1. `referencePixelsPerUnit / sprite.pixelsPerUnit`로 되돌려 **"그림의 픽셀 = UI 단위"**로 만든다.
2. 그러고도 모서리 둘이 칸보다 넓으면(HUD 액션 줄처럼 칸이 44.4px밖에 안 될 때) **칸의 90%**에
   맞춰 한 번 더 줄인다.
3. 칸 크기를 아직 모를 때(레이아웃 전, rect가 0)는 1번만 하고 넘어간다.

**09-29에 HUD가 쓰던 손계산 배수(`50 / (slot*0.45)`)도 이걸로 갈아 치웠다.** 그건 그림의
`pixelsPerUnit`을 모른 채 어림잡은 값이었다 — 우연히 크게 안 틀렸을 뿐이고, 실제로는 테두리가
칸보다 넓어져 유니티가 알아서 눌러 주고 있던 상태였다. 바꾼 뒤 **HUD 버튼 열 칸도 같이 제대로
둥글어졌다**(아래 확인).
