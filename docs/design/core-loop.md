# 코어 루프 — 채굴과 레이싱의 상호 강화

2026-09-11 개정. 기획서 v0.2의 "자원 배분" 구조를 "상호 강화 나선"으로 바꾼다.

## 무엇이 바뀌었나

**v0.2 (기각)** — 같은 광물을 채굴 장비에 쓸지 레이싱 부품에 쓸지 고르는 줄다리기.
한쪽에 투자하면 다른 쪽이 늦어지는 구조였다. 어느 쪽을 골라도 "다른 걸 못 했다"는 느낌이 남는다.

**v0.3 (확정)** — 채굴이 레이싱을 먹이고, 레이싱이 채굴을 먹인다.
두 축이 서로를 밀어 올리므로 어떤 행동도 헛되지 않는다.
방치형에서 오래 쓰인 구조이고, 이 게임에는 특히 잘 맞는다.
채굴만 파도 막히고 레이싱만 파도 막히게 만들어서, 두 축을 번갈아 올리는 것이 유일한 길이 된다.

## 한 바퀴

```
행성 도착
   ↓
탐험 — 채굴차가 표면을 천천히 돌며 보물·광맥을 발견한다 (자동, 오프라인에도 진행)
   ↓
채굴 — 발견한 것 중에서 골라 캔다. 광물과 보석이 쌓인다
   ↓
강화 — 광물로 세 가지를 올린다
        · 채굴 도구 (곡괭이·드릴·레이저)  → 캐는 속도와 캘 수 있는 등급
        · 채굴차 (엔진·화물칸·탐지기)     → 탐험 속도와 발견 확률
        · 레이싱카 부품 제작              → 레이스 성적
   ↓
레이스 — 연료를 써서 출전. 이기면 ★채굴차 전용 강화 부품★을 준다
   ↓          (이게 이 구조의 핵심이다. 레이싱 보상이 채굴로 돌아온다)
   ↓
더 빨리 채굴 / 더 높은 등급 보물을 캘 수 있게 됨
   ↓
광물이 더 빨리, 더 좋은 게 쌓임 → 레이싱카를 더 강화
   ↓
더 높은 등급 레이스 승리 → 더 좋은 채굴차 부품
   ↓
(반복)
   ↓
행성의 레이스를 모두 정복 (그랑프리 1등)
   ↓
다음 행성으로 워프 — 새 광물, 새 보물 등급, 처음부터 다시
```

## 두 축이 서로를 막는 방식

나선이 돌게 하려면 한 축만 파서는 못 넘어가는 벽이 양쪽에 있어야 한다.

| 막는 것 | 뚫는 방법 | 이유 |
|---|---|---|
| 높은 등급 보물은 캐지지 않는다 | 레이스에서만 나오는 채굴차 부품이 필요 | 채굴만 파는 길을 막는다 |
| 상위 레이스는 출전이 안 된다 | 그 행성 광물로 만든 부품 세트가 필요 | 레이싱만 파는 길을 막는다 |
| 다음 행성으로 못 간다 | 그랑프리 1등 | 행성 단위 진행을 만든다 |

레이스 보상은 광물이 아니라 **채굴차 부품**이어야 한다. 광물로 주면 그냥 채굴의 대체재가 되어
나선이 풀린다. 마찬가지로 채굴로는 레이싱카 부품을 **만들 수만** 있고 완성품이 나오지는 않는다.

## 탐험과 보물

기존 기획에는 광맥만 있었다. 여기에 보물을 더한다.

- **광맥** — 흔하다. 기본 광물이 나온다. 채굴차가 지나가다 자동으로 캔다.
- **보물** — 드물다. 등급(C~S)이 있고, 등급마다 요구 채굴 도구 등급이 있다.
  발견은 자동이지만 캘지 말지는 플레이어가 고른다. 못 캐는 등급은 목록에 남아서
  "저걸 캐려면 도구를 더 올려야 한다"는 다음 목표가 된다.

### 방치형인데 탐험이 되는가

된다. 나눠서 처리한다.

- **발견은 자동.** 접속하지 않은 동안에도 탐험이 진행되어 발견 목록이 쌓인다.
  돌아오면 "없는 동안 보물 3개, 광맥 11개를 찾았다"가 뜬다.
- **선택은 수동.** 무엇을 캘지, 무엇을 남겨 둘지는 플레이어가 고른다.
  화물칸 상한이 있으니 전부 캘 수는 없고, 여기서 판단이 생긴다.

이러면 자리를 비운 시간이 낭비가 아니고, 돌아왔을 때 할 일이 분명하다.

## 정해진 것 (2026-09-14 새벽 세션, L-01~L-03)

- **채굴차 부품 슬롯 = 5개(Tool/Cargo/Engine/Detector/Refinery)**, `MiningRig`의 기존 레벨 필드와
  1:1 대응한다. 레이싱카처럼 별도 오브젝트를 슬롯에 끼우는 대신, 레이스 보상(`RigPartReward`)이
  해당 슬롯 레벨을 올리는 방식. `Core/RigParts.cs`.
- **레이스 보상 = 채굴차 부품.** `DefaultData.QuartzLocalRaceRewards()`로 쿼츠 로컬 레이스 3개가
  각각 다른 슬롯(Tool/Cargo/Engine)을 하나씩 올려 준다. 광물이 아니라 이게 나와야 나선이 돈다.
- **탐험·발견·선택 채굴 구조 — 코어 모델.** `Core/Exploration.cs`의 `ExplorationSimulator.Discover`가
  경과 시간(온라인·오프라인 공통) 동안의 보물 발견 목록을 seed 하나로 재현 가능하게 만든다.
  광맥은 기존 `MiningSimulator`가 그대로 자동 산출(시간당 광물)을 계산하고, 여기서는 드문 보물만
  다룬다. 각 발견은 `CanMineNow`(지금 도구로 캘 수 있는지)를 들고 있어 — 못 캐도 목록엔 남아
  "도구를 올려야 한다"는 다음 목표가 된다.
- **보물 데이터 모델.** `TreasureGrade`(C~S) + `TreasureDef`(등급, 요구 도구 레벨, 광물 환산치).
  `DefaultData.QuartzTreasureDefs()`에 쿼츠용 4종 플레이스홀더.
- **오프라인 발견 목록(L-04, 9/12 오후).** `ExplorationSimulator.DiscoverOffline`이 광물(`MiningSimulator.Offline`)과
  보물(`Discover`)을 한 벌(`OfflineDiscoveries`)로 묶는다. 탐험도 화물칸 상한만큼만 인정 — 화물칸이 다 찬
  뒤에는 채굴차가 멈춰 있는 셈이라 그 이후 발견이 계속 쌓이면 광물 쪽과 앞뒤가 안 맞아서 맞췄다.
- **실시간 채굴 루프(D04-N, 9/12 오후).** `Core/MiningRun.cs`의 `MiningRunState`가 `MineralsPerHour` 공식을
  "이동 → 광맥 도착 → SecondsPerVein만큼 채굴 → YieldPerVein 획득"으로 프레임 단위로 풀어 쓴다.
  `Assets/Scripts/Mining/MiningController.cs`가 매 프레임 `Advance`를 부르고, 채굴 단계 동안
  `SurfaceMover.isMoving`을 꺼서 채굴차가 광맥 앞에 멈추게 한다. `GameState`(Mining/Racing/Result) +
  `GameFlowController`는 나중에 레이스·결과 화면이 생겼을 때 같은 자리에 붙일 상태 전환 뼈대.

## 정해진 것 (2026-09-12 밤 세션, D05-N·L-05)

- **채굴 장비 업그레이드 비용 = 지수 증가.** `Core/RigUpgrade.cs`의 `UpgradeCost`가 Tool/Cargo/Engine
  세 슬롯의 다음 레벨 비용을 계산한다(레벨당 성장률 1.28~1.48배, 상한 30/10/10). 위 "체감 효과는
  강화 비용을 지수로 올려서 넣는다"는 생각을 실제로 구현한 지점.
- **L-05 봇 시뮬레이션으로 1차 확인.** `Core.Tests/BalanceSim.cs`(`dotnet run -- sim`)가 "제일 싼
  업그레이드를 산다" 봇으로 30분마다 로컬 레이스 승리를 가정해 돌려본다. 처음 잡은 성장률
  (1.22~1.35)로는 **쿼츠 Tool/Cargo/Engine이 3.1시간 만에 전부 최대치**에 도달해 나선이 아니라
  즉시 터지는 그림이었다 — 성장률을 1.28~1.48로, 기본 비용도 올려서 8시간으로 늘렸고 뒤로 갈수록
  구매 간격이 완만히 벌어지는 걸 확인했다. **정확한 목표 시간(하루 분량? 이틀?)은 아직 안 정했다** —
  이번 조정은 "터지지 않는다" 정도의 1차 방어선이고, 최종 수치는 여전히 P4 봇 시뮬레이션 몫이다.
- **버그 발견·수정**: 레이스 무료 보상(`RigPartApply.Apply`)이 슬롯 상한을 안 지켜서 Cargo/Engine이
  10을 넘어가고 있었다. Models.cs 필드 주석에 있던 상한(Tool 30 / Cargo·Engine 10 / Detector·Refinery 5)을
  실제로 클램프하도록 고쳤다 — 강화 상점(`UpgradeCost.Apply`)은 원래도 상한에서 멈췄지만 레이스
  보상 경로는 그렇지 않았던 것.

## 아직 안 정한 것

- 보물 등급별 요구 도구 등급의 구체적 수치(지금은 1/11/21/26 플레이스홀더). P4 봇 시뮬레이션에서 맞춘다.
- 보물 발견 확률(`chancePerCycle`, 지금 0.05 플레이스홀더)도 P4에서.
- 레이스 등급과 채굴차 부품 등급의 대응. 로컬 레이스가 C를, 그랑프리가 S를 주는 식으로 갈지.
  지금은 `RigPartReward.LevelBonus`가 전부 +1 고정 — 등급별 차등은 아직 없다.
- 업그레이드 비용의 정확한 목표 페이싱(쿼츠 하나를 다 채우는 데 며칠이 걸려야 하는지). 위 L-05는
  "당장 안 터진다"만 확인했지 목표 시간을 정하고 맞춘 게 아니다.
- 업그레이드 비용을 지금은 원석(RawMinerals)에서 낸다 — 제련(RefineryLevel) 로직 자체가 아직
  없어서 임시로 그렇게 했다. 제련이 생기면 정제 광물 기준으로 바꿔야 한다(`MiningController.TryUpgrade`
  주석에 TODO로 남겨둠).
