# 세션 로그·피드백 파일 형식 (D17-M)

D17-N에서 만든 두 파일의 형식. 둘 다 `Application.persistentDataPath`에 생긴다
(Android면 기기 내부 저장소 앱 전용 폴더, PC/Steam이면 사용자 폴더 아래 회사명/제품명 폴더,
WebGL이면 브라우저 IndexedDB 가상 파일시스템 — 코드는 `SessionLogger.cs`/`FeedbackLog.cs` 참고).

## session_log.csv

`SessionLogger.cs`가 씀. 앱이 화면 앞에 있던 구간(세션) 하나당 한 줄. 첫 줄은 헤더.

```
start_unix,start_iso_utc,duration_seconds
1758067200,2026-09-16T23:00:00Z,742
```

- `start_unix` — 세션 시작 UTC epoch초. 정렬·기간 계산은 이 값을 쓴다.
- `start_iso_utc` — 같은 시각을 사람이 읽기 좋게 ISO 8601로. 파싱 없이 눈으로 훑어볼 때 쓴다.
- `duration_seconds` — 그 세션이 이어진 시간(초). 항상 0 이상(시계가 거꾸로 가도 음수를 안 남긴다).

"세션"의 경계는 접속/종료가 아니라 **포그라운드 진입/이탈**이다 — 홈 버튼으로 백그라운드에
갔다가 돌아오면 두 줄로 나뉜다. D23-N(관문 판정: 3일 연속 접속 인원, 이탈 지점)에서 이 로그를
읽을 때 참고할 것:

- "그날 접속했다"는 `start_iso_utc`의 날짜 부분(UTC 기준, KST와 9시간 차이 — 자정 근처 세션은
  날짜가 하루 밀려 보일 수 있다는 뜻, 분석할 때 KST로 변환해서 볼 것)만 보면 된다.
- "하루 총 플레이 시간"은 같은 날짜의 `duration_seconds`를 다 더한 값이다.
- "이탈 지점"은 이 로그만으로는 안 보인다 — 어느 화면에서 마지막으로 끊겼는지는 지금 안 남기고
  있음(필요해지면 SessionLogger에 "마지막으로 연 화면" 필드를 추가할 자리로 남겨 둔다).

## feedback.txt

`FeedbackLog.cs`가 씀. 자유 텍스트 블록이 시간순으로 이어 붙는다. 파싱용이 아니라 사람이 그대로
읽는 파일이라 CSV가 아니라 평문이다.

```
[2026-09-16T23:10:00Z]
저장 씬 두 번째로 켰을 때 튜토리얼 배너가 다시 떴어요

[2026-09-16T23:42:00Z]
설정 화면 프레임 60 눌러도 안 오르는 것 같음
```

- 저장 버튼을 누른 순간 클립보드에도 같은 텍스트가 복사된다(`GUIUtility.systemCopyBuffer`) —
  파일을 직접 꺼내지 않아도 카카오톡 등에 바로 붙여넣어 보낼 수 있다.
- 빈 줄/공백만 있는 내용은 저장하지 않는다(`FeedbackLog.Append`가 `false`를 돌려주고 화면엔
  "내용을 적어 주세요"만 뜬다).

## 알려진 한계 (아침 확인 필요와 별개로 기록)

- 두 파일 다 기기에만 남는다 — 서버 업로드가 없어서, 지인 5명의 파일을 모으려면 각자
  `feedback.txt`/`session_log.csv`를 직접 꺼내 보내 줘야 한다. 지인 테스트 규모(5명, 3일)에는
  이 정도가 서버를 새로 만드는 것보다 싸다고 보고 이렇게 결정했다 — 만약 D20–D22 테스트 중
  파일을 못 꺼내는 문제가 생기면(플레이스토어 미배포 APK라 파일 탐색기 접근이 막히는 기기 등)
  그때 클립보드 복사만으로 충분한지 다시 볼 것.
- WebGL 빌드는 페이지를 새로고침하면 그 사이 쓴 내용이 남는지 불확실하다(IndexedDB 동기화
  시점, 이 클라우드 세션은 에디터가 없어 확인 못 함 — D17-N 부트스트랩 안내 문구에도 남겨 둠).
  실제 지인 테스트는 안드로이드 빌드로 하므로 이 한계는 크게 문제되지 않을 것으로 본다.
